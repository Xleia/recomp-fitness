# RECOMP｜本地加密健身管理 PWA

这是可部署到 GitHub Pages 的**公开静态网页应用**，不是私有网站。个人的体重、腰围、营养目标、训练历史和饮食记录不写入公开仓库；只有你在浏览器首次填写的数据才会被保存在本地**加密保险库**内。

## 功能

- iPhone主屏幕安装、Service Worker离线缓存
- 首次创建至少12字符的解锁密码；按日本时间每日首次解锁，当天再次打开自动免密；切换到后台会丢弃内存密钥，手动锁定会取消当日免密
- Web Crypto：PBKDF2-HMAC-SHA256（600,000次、随机16字节盐），AES-256-GCM（随机12字节IV和认证标签）
- 8周腿、胸＋三头、背＋二头、肩＋核心训练日志，每组重量/次数/完成情况
- 工作日外食选项、周六全天自由饮食、每日营养输入和合计
- 身体测量与趋势图
- 密码修改（重新加密）、加密JSON备份／恢复、旧版明文数据迁移并删除

## 部署到 GitHub Pages

1. 在 GitHub 账号下建立公开仓库，例如 `recomp-fitness`（空仓库最好）。
2. **仅上传本ZIP解压后的文件**，不要上传旧版HTML、私人备份或记录；文件必须位于仓库根目录。
3. 进入 `Settings → Pages → Build and deployment`：Source 选择 `Deploy from a branch`，Branch `main`，Folder `/(root)`，保存。
4. 等待发布，使用 HTTPS 网站网址访问，例如 `https://<你的用户名>.github.io/recomp-fitness/`。
5. iPhone Safari打开网址 → 分享 → 添加到主屏幕。**首次打开需要联网，让离线资源成功缓存**。
6. 第一次启动时设置强密码，并在设备上输入自己的身体与热量目标。建议用自己以前确认的计划数据，不要把数字写回公开源代码。
7. 保存一条训练记录 → 退出再打开（当天应自动解锁）→ 点击「锁定」（应恢复密码验证）→ 输入密码重新解锁；断网重新打开测试。导出一次加密备份，验证文件存在。

## 隐私与安全局限

- **网站和JavaScript仍公开**；静态训练记录始终加密，但启用当天免密后，IndexedDB 会保存不可导出的 AES 解密密钥供当日自动解锁。这降低了同一设备被他人使用时的锁定保护，不能防范被篡改的脚本或设备恶意程序。不要把它当作经过独立安全审计的医疗级产品。
- 密码不会上传，遗忘密码无法重置。加密备份仍必须使用生成备份时的密码解密。
- 使用浏览器 `localStorage` 保存**加密密文**（不保存明文密码或训练记录）；当日免密密钥存在 `IndexedDB`，按日本时间日期校验，跨日需要再次输入密码，手动锁定将撤销当日免密。部分浏览器可能无法持久化 CryptoKey，此时照常使用密码解锁。iOS可能清理网站数据，必须定期导出加密备份。
- 为确保本地运行，无第三方统计脚本、登录服务、远程字体或数据库；网站服务器仍可能看到普通访问元数据（IP、时间等）。
- 旧版PWA曾把个人身体数字写入HTML，且可能保存未加密记录。如果你已上传旧版到公开GitHub，**新提交不能删除Git历史及第三方缓存**。最稳妥的方式是删除旧仓库、用此ZIP从零创建新仓库；但已被外部复制的历史不可收回。
- 若原网址曾在iPhone缓存旧版，可以在完成必要的数据迁移和备份后清理Safari网站数据／删除旧主屏幕App，再用新网址重新安装。不要在尚未备份时清理浏览器数据。

## 数据格式与不允许上传的内容

- 本地加密密文：`localStorage` 键 `recomp.encrypted.v2`。当日免密使用 `IndexedDB` 数据库 `recomp.daily-unlock.v1`，只在本机保存不可导出的加密密钥与本次验证的日期、salt；不储存密码明文。
- 备份文件名 `RECOMP_encrypted_backup_YYYY-MM-DD.json`；可以离线保存，但不要上传到公共仓库。
- 不要把个人照片、体重、腰围、健康信息、账号密码、个人记录 JSON 提交到GitHub仓库。

## 开发测试

可在Windows通过任何静态HTTP服务器预览 `http://localhost:8000`，浏览器把 localhost 视为安全上下文。普通 `file://` 本地预览不应作为安装方式。开发时可使用浏览器开发者工具检查只有加密密文存储在本地。

## 食物营养库与计算器（功能分支版本）

打开「每日饮食」→「食物营养库」，搜索食品名称（日文或常用中文别名）并点击「加入计算」。填写食用份量后，可选择「记入早餐／午餐／加餐／晚餐」，然后**返回每日饮食页面并点击「🔒 加密保存当天饮食」**。当天总量会将食物明细与原有手动补录合并。为了避免重复统计，添加食物明细后不要再在手动栏填入同一份食物的营养值。

- 预置 2,538 种日本食品，网页首次联网加载并随 PWA 资源缓存，之后可离线使用。支持中文常见别名与完整日文食品名，注意区分生／熟、带皮／去皮。
- 计算器按每 100 g 的源数据 × 实际重量／100 计算；部分明确密度的饮品支持 ml，鸡蛋与香蕉支持标有**估算可食重量**的个数／根数选项。不能把任意食品的 g 与 ml 自动视作等值。
- 支持收藏、自定义品牌食品（每 100 g 或每 100 ml 标签值）、常用餐模板与饮食明细，均保存在原有加密保险库中，沿用当天免密与加密备份。
- 旧备份无需手动修改：旧式仅记录「手动餐次营养」的饮食数据仍可读取；新的 `foodItems` 为可选字段，不修改原有保存条目。
- 每次更改食材明细后必须点击「加密保存当天饮食」；若离开网页未保存，草稿不会持久化。手工餐次编辑进入食物库时会在内存中暂存，避免立即丢失。

### 数据来源与限制

初始静态 CSV 是由 [Yocchan1513/omame-nutrition-api](https://github.com/Yocchan1513/omame-nutrition-api) 整理的、基于文部科学省[《日本食品标准成分表（八订）增补2023年》](https://www.mext.go.jp/a_menu/syokuhinseibun/mext_00001.html) 的 2,538 种食品数据，并非直接下载的官方原始 Excel 文件。该整理数据对缺失值、微量值进行了数值规范化，故**不能用它判断微量值与缺失值的区别**，也不等同于2026年更正后的官方数据库。表内通用食品值与品牌产品包装标签可能不同，后者请在「自定义品牌食品」中录入。

个人食品、食谱模板及实际饮食记录**不上传到 GitHub**。用户自行导出加密 JSON 备份时，请妥善保管密码。iPhone 首次加载新版需联网以缓存数据文件；上线前先导出旧版加密备份，升级后验证旧训练、测量、饮食记录及离线操作。

本期实现食物库、重量计算、常用餐、自定义食品、每日记录联动；批量自然语言输入、扫码识别、官方数据自动增量更新尚未开发。
